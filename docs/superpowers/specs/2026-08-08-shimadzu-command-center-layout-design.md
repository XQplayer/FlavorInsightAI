# 岛津 GC-MS C 方案指挥台布局设计

## 目标

将岛津分析页面从“连续纵向卡片”调整为面向长时间运行与复核的分析指挥台。保留现有上传、运行设置、七步流程、实时监控、错误提示、账号和历史任务功能，不修改 Worker、API、Supabase、文件契约或任何分析计算。

## 视觉与信息结构

1. 桌面端采用双区结构：左侧为固定宽度的流程状态轨道，右侧为当前任务内容区。
2. 左侧流程轨道保留七个节点、状态图标、进度和阶段说明；节点改为纵向排列，当前节点有清晰的蓝色状态强调。
3. 右侧优先显示输入/设置或当前任务工作区；实时监控保持深色控制台，作为运行期间最强的视觉焦点。
4. 顶部 Hero 收紧为紧凑的工作台标题和浏览器分析引擎状态，不增加背景图片、复杂插画或额外指标。
5. 账号、错误、恢复提示和历史任务保持原有功能，使用较低视觉权重的状态条和可读的错误区域。

## 响应式行为

- `min-width: 1080px`：流程轨道位于左侧并保持适度 sticky，右侧内容区占主要宽度。
- `768px–1079px`：流程轨道变为横向可滚动区域，输入与监控保持单列，避免挤压操作控件。
- `<768px`：全部内容单列；流程节点压缩为可横向浏览的步骤条，按钮和表单保持原有键盘顺序与触控尺寸。
- 保留 `prefers-reduced-motion`，不引入新的必须动画。

## 视觉语言

- 沿用现有深蓝导航、深色实时监控和蓝色操作色，减少无意义的圆角卡片层级。
- 采用更明确的 12/16/24/32px 间距节奏，提升标题、控件组、监控区之间的层次。
- 流程轨道使用细边界和状态色表达阶段，不使用装饰性渐变或额外图表。
- 错误、警告、等待、完成状态继续沿用现有语义颜色。

## 约束与验收

- 只修改 `ShimadzuAnalysisPage.jsx` 的布局 class（如确有必要）和对应 CSS/布局测试，不改分析代码。
- 现有页面行为、ARIA 属性、键盘顺序、文件下载和任务恢复必须保持不变。
- 使用现有依赖，运行 lint、Shimadzu 测试、浏览器测试和生产构建。
- 在 375px、768px、1024px、1440px 宽度检查无横向溢出，流程、上传、设置和监控均可发现并操作。
