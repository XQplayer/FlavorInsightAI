# 岛津 GC–MS 数据控制舱界面设计

## 设计结论

岛津数据分析页面采用 C 方案“数据控制舱”。页面从 FlavorThresholdDB 首页进入后，不再显示全站顶部导航，只保留一个明确的“返回首页”入口。登录、管理员审批、任务台、模板下载、实时监控和完整分析功能全部保留，但重新组织到岛津工作区内部。

本轮只重构页面信息架构与视觉表达，不修改分析算法、Web Worker、API、Supabase、权限规则、工作簿契约、七步流程、QC 规则或输出文件。

## 视觉方向

- 工作模式：Operate，面向需要连续上传、配置、运行、监控和下载结果的科研用户。
- 主视觉：深海军蓝和石墨黑背景，冷蓝作为主操作色，青绿色表示通过或运行正常，红色只用于失败和高优先级异常。
- 组件质感：边框定义层级，阴影弱化；减少大面积白色卡片和过度留白。
- 字体层级：标题强调实验平台身份，正文优先可读性；状态、日志和编号采用紧凑但不低于 11px 的字号。
- 动效：沿用现有 GSAP，只用于页面进入、阶段变化、进度和状态反馈；支持 `prefers-reduced-motion`。

## 页面结构

### 1. 最小顶部栏

- 左侧保留 HXQLab 与 Shimadzu 页面身份，不作为导航菜单。
- 右侧只提供“返回首页”入口。
- 不显示“首页、FlavorThresholdDB、岛津气质分析、语言、任务台、账号”等横向全站导航项目。
- 任务台和账号入口移动到工作区，不丢失功能。

### 2. 控制舱标题区

- 标题使用“岛津风味数据分析控制舱”。
- 副标题保留完整流程描述：原始峰表、化合物筛查、平行补建、半定量、统计和作图矩阵。
- 右侧显示浏览器分析引擎状态和当前账号状态。
- 未登录时，账号状态提供清晰的登录入口；已登录时显示姓名、审批状态和管理员身份。

### 3. 输入文件与运行设置

桌面端首屏采用左右两列：

- 左列“准备输入文件”占较宽区域，纵向显示两个紧凑上传模块。
- 每个上传模块保留文件说明、选择文件、文件状态和下载示例或模板入口。
- 右列“运行设置”保留任务名称、连续执行、CV 筛查、CV 阈值和开始分析按钮。
- 文件未就绪或权限不足时，开始按钮继续遵循现有禁用逻辑，并显示缺失条件。
- 两个文件通过检查后，明确显示“文件已准备，可以开始分析”。

### 4. 七步流程带

- 七步流程位于上传和设置之后、监控区之前。
- 桌面端横向完整显示；中小屏允许横向滚动，但不遮挡顶部区域。
- 每个节点保留编号、名称和完成、当前、待处理、警告、失败状态。
- 节点只作为流程状态和复核入口，不改变现有运行顺序。

### 5. 实时分析监控

- 未运行时显示待机状态和输入准备说明，不出现虚假的运行数据。
- 运行时突出当前步骤、总进度、当前工作内容和最近日志。
- 失败时自动结束运行状态，显示失败步骤、具体原因、错误码和已保存的阶段结果入口。
- 等待复核时显示复核原因与继续操作。
- 完成时突出结果 ZIP、报告和关键质量统计，日志降低优先级。

### 6. 任务台

- 与实时监控并列显示在桌面端首屏下半区。
- 普通用户只看到自己的任务、结果和错误信息。
- 管理员可查看所有用户任务，并按既有权限下载用户上传的原始工作簿及已生成结果 ZIP。
- 保留结果下载、重新运行、删除结果、查看错误和任务报告入口。
- 删除按钮继续遵循既有权限：普通用户只能删除自己的结果，管理员可删除任意用户结果。

### 7. 账号与管理员功能

- 账号不再占用顶部导航，改为控制舱标题区的状态入口和页面内部账号面板。
- 未登录、待审批、已批准、被拒绝、已停用和管理员状态均保留。
- 管理员审批队列、首次管理员认领和退出登录功能不删除。
- 账号面板按需展开或滚动定位，避免干扰主要分析路径。

## 页面状态

### Idle

输入文件、运行设置和模板下载优先；监控区显示待机说明；任务台显示最近任务。

### Running

当前阶段和日志成为最高优先级；流程带同步高亮；禁止造成任务冲突的操作。

### Waiting Review

在监控区和当前流程节点同时显示复核原因、影响范围和继续按钮。

### Failed

运行状态立即结束，不保持“处理中”；错误区域显示人类可理解的原因、错误码、失败步骤、建议检查项和可下载的阶段性结果。

### Complete

结果下载、任务报告、完成时间和 QC 状态优先；提供保留或删除结果的入口。

## 响应式规则

- `≥ 1280px`：输入与设置两列，监控与任务台两列，七步完整横排。
- `1024–1279px`：维持两列但缩小侧栏，日志和任务操作允许换行。
- `768–1023px`：输入、设置、监控和任务台改为单列；七步流程横向滚动。
- `< 768px`：全部单列，顶部栏只保留品牌与返回首页；上传操作纵向排列。
- `375px`：无页面级横向溢出，按钮和输入控件触控高度不低于 44px。

## 可访问性与文案

- 保留现有键盘顺序、焦点环、ARIA 标签、`aria-live` 和状态图标。
- 颜色不是唯一的状态表达方式，状态同时使用文字和图标。
- 普通用户界面不直接显示 `manifest` 等开发术语。
- 错误信息同时提供简明原因和可用于技术排查的错误码。
- 运行日志最小字号 11px，辅助说明最小字号 12px，正文最小字号 14px。

## 不变的功能与契约

- 原始工作簿和样品信息表的文件校验规则。
- 七步 Shimadzu 数据处理算法与执行顺序。
- Worker 消息、进度、复核、失败和结果返回契约。
- Supabase 登录、审批、任务、权限和保留期限。
- CV 筛查开关、阈值及输出逻辑。
- 模板下载、任务恢复、结果下载和删除权限。
- OAV 当前保持关闭，不在本轮新增。

## 验收标准

1. 岛津路由不再显示全站顶部导航，只保留返回首页入口。
2. 登录、管理员审批、任务台、模板下载、分析监控和结果操作全部可访问。
3. 首屏采用数据控制舱视觉，并在桌面端形成上传/设置和监控/任务台两组高效布局。
4. Idle、Running、Waiting Review、Failed、Complete 状态都有清晰展示。
5. 375px、768px、1024px 和 1440px 布局可用，无顶部遮挡和页面级横向溢出。
6. 不改变分析逻辑、Worker、API、Supabase、文件契约和输出结果。
7. `pnpm run lint`、`pnpm run build`、`pnpm run test:shimadzu`、`pnpm run test:shimadzu-browser` 和 Shimadzu E2E 验证通过。
