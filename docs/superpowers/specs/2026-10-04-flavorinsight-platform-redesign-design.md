# FlavorInsight AI 全站设计与网址迁移

日期：2026-10-04
状态：已确认设计，待实施计划与代码实施
适用仓库：当前 `XQplayer/FlavorThresholdDB`，计划改名为 `XQplayer/FlavorInsightAI`

## 1. 决策与边界

FlavorInsight AI 是平台品牌名；FlavorThresholdDB 继续是平台内香气阈值与风味描述数据库的名称。全站统一设计覆盖首页、登录页、数据库入口与检索工作台、数据处理、数据分析以及资源中心。按页面分阶段落地，不改变现有检索、岛津分析与导出的科学规则。

新本地主页为 `http://127.0.0.1:5174/FlavorInsightAI/`。线上 GitHub Pages 项目站点以改名后的仓库 `FlavorInsightAI` 为承载，目标网址为 `https://XQplayer.github.io/FlavorInsightAI/`。旧 `/FlavorThresholdDB/` 网址不承诺继续可用，也不建设旧站跳转；仓库内当前使用说明中的旧平台链接应更新，`PROJECT_HISTORY.md` 等历史记录保留原始事实。数据库模块在新路径下仍保留自身检索入口，不因平台品牌改名而改称 FlavorInsight AI 数据库。

本轮全站登录页只完成视觉与入口，不接入新的全站身份认证，不要求登录才能使用当前本地功能，不收集或提交账号密码。岛津模块现有的可选账号/云端代码及权限逻辑不由新登录页替换。页面必须明确标示账号功能尚未启用，并提供“继续本地使用”入口；不得绘制貌似可提交但实际无效的表单。

## 2. 用户体验与页面职责

### 全站框架

顶部统一放置品牌、首页、FlavorThresholdDB、数据处理、数据分析、资源中心，以及中英文、主题和账号入口。当前能力与规划能力始终使用不同的文字状态标识。公共导航与主题偏好跨页面一致；窄屏以可操作的折叠菜单呈现，不遮挡内容或键盘焦点。

### 首页

作为品牌层，清楚说明“仪器数据—化合物鉴定—风味数据库—风味贡献评价—AI 解析与预测”的研究链，同时逐项标注已上线、开发中、规划中。首屏提供进入数据库与数据处理的真实入口；示例数据必须可追溯，不能把未来的智能体、模型或分析能力说成已上线。后续展示平台模块、证据链原则和使用边界。

### 登录页

采用已确认的左右结构：全屏环境背景及深色遮罩，左侧品牌定位、能力说明与可追溯研究理念，右侧高对比度悬浮卡片。右侧以账号功能状态说明和“继续本地使用”为当前主操作，登录字段只可作为明确标注的未启用预览，不接受输入或提交。避免“忘记密码”“保持登录”等尚不存在的虚假功能。未来接入真实认证时，应沿用本页结构但另行设计会话、审批、错误、隐私和恢复流程。

### FlavorThresholdDB 与检索

数据库概览继续介绍数据来源、热门化合物和检索入口；CAS、名称、阈值、来源、结构等科研证据保持现有可复核路径。检索工作台、结果表、来源徽标和导出不因视觉改版改变数据语义。数据密集区域采用稳定、清晰的实色面板。

### 数据处理

保留分析流程配置、数据导入、过程监控、质量门禁、错误证据和结果导出的现有执行逻辑。流程状态、警告与失败同时以文字和图标呈现，绝不只靠颜色。玻璃效果不能覆盖输入、日志、表格、质量门禁和数值。

### 数据分析与资源中心

统一页面框架并准确标示已可用、开发中、规划中。数据分析暂不冒充已部署的 AI 结果。资源中心区分已核验资源与规划内容，保留来源和更新状态。

## 3. 视觉系统

视觉策略是“品牌页面强调玻璃质感，科研工作台强调清晰数据”。参考 `VoltAgent/awesome-design-md` 中 Apple `DESIGN.md` 的留白、精确排版和受控层级，但不复制其商标、页面内容或完整品牌配色。现有根目录 `DESIGN.md` 是未提交的岛津工作台设计文件，必须保留；实施时将所选 Apple `DESIGN.md` 复制到独立参考目录并保留许可与出处，再从中提炼 FlavorInsight AI 自有设计规范，不覆盖根目录文件。

背景基础色：雾灰 `#D9DDD9`、灰蓝 `#AEB9BD`、灰紫 `#B7B1BD`、暖灰白 `#ECEAE5`；主文字基色 `#252729`。背景色之间只能使用低对比、缓慢且自然的明度过渡。品牌操作色仅设一种，成功/警告/失败作为语义状态色独立使用；操作色具体数值在实施前通过页面对比度样张确定，不能采用高饱和蓝紫粉渐变。

玻璃质感用于悬浮导航、登录卡边缘和少量重要控件：通过多层透明镜片、弧形边缘高光、局部低强度反射和明确的前后层级表达；不依赖高透明度或全页模糊。浏览器内的光学效果不得降低文字对比度。`backdrop-filter` 不可用或用户偏好减少透明时，退化为实色表面。数据表、输入框正文区、错误详情和运行日志使用不透明或接近不透明的表面。

避免彩虹玻璃、高饱和渐变、肥皂泡、漂浮水晶、液态金属、赛博朋克、无意义 3D、全组件发光、过度模糊及廉价塑料感。界面应呈现低噪声、轻盈、精密的系统工具气质。

字体需支持中文与英文并兼顾 Windows 工作站渲染。大标题与正文有清晰字号阶梯；正文原则上不小于 16px，密集科研表格可按既有可读规范单独调校。正文与控件文字目标达到至少 WCAG AA 普通文字 4.5:1 对比度。交互目标至少约 44×44px，具备明显键盘焦点、触控间距、加载与错误反馈。动画不承载唯一信息，遵循 `prefers-reduced-motion`。桌面、平板和手机分别验收，避免横向页面溢出。

Galaxy 控件库只作为组件候选来源。采用某个按钮、输入或卡片前必须检查具体源码、交互状态、许可与署名，并适配现有 React/CSS 和全站视觉令牌；不因“玻璃”标签而照搬不适合科研界面的特效。

## 4. 技术边界与迁移顺序

1. 先建立项目自有设计令牌与页面级覆写规则。保留现有岛津工作台的状态语义和两种主题偏好，不对整个系统做机械反色。
2. 先完成首页和登录页，再逐页统一数据库、数据处理、数据分析和资源中心的导航、容器、表单与状态组件。可采用渐进式页面改版，但所有页面最终遵循同一全站规范。
3. 新增明确的登录页路由与浏览器标题。未启用全站认证期间，账号入口进入状态明确的登录页；“继续本地使用”返回真实可用页面。旧岛津可选账号模块保持独立。
4. 将 Vite 基础路径和内部路由改到 `/FlavorInsightAI/`。同步更新静态深链接生成、公共资源引用、测试、脚本、环境配置说明、项目文档及部署工作流。逐条区分“平台路径”与仍应保留的数据库产品名、源仓库历史记录或外部数据标识。
5. 只有在本地新路径构建与深链接通过后，才重命名 GitHub 仓库、更新本地 `origin`，再部署并验收新的 Pages 路径。仓库改名是发布操作，不与未验证的 UI 修改捆绑执行。旧线上路径不做跳转承诺。
6. 不自动将原始工作簿或分析结果上传到云端。改版不改变现有本地分析与可选云端留存的实际行为及文案边界。

## 5. 错误处理与验收

页面加载、深链接、未启用账号入口和外部服务不可用均应给出明确状态及下一步操作；不能把占位内容画成可用功能。登录页不能向任何服务提交密码。质量门禁失败必须维持现有错误码、错误证据和部分结果下载能力。

验收标准：

- 本地首页及数据库、检索、处理、分析、资源、登录深链接均在新基础路径下直接加载；旧路径不作为通过条件。
- GitHub 仓库改名后，新 Pages 首页与各深链接可访问，资源无 404，内部导航留在新路径；用户文档的旧平台链接已更新。
- 中英文、深浅主题及窄屏布局可用；在 375px、768px、1024px、1440px 宽度检查无页面级横向溢出。
- 键盘导航、可见焦点、表单状态说明、颜色对比、减少动效和减少透明回退通过检查。
- 现有平台、静态路由、数据库检索和岛津浏览器流程测试通过；代表性本地检索、分析与导出行为没有因 UI 改版改变。
- 未启用的全站登录无虚假提交；数据分析中的未来 AI 能力继续明确标记为未部署。
