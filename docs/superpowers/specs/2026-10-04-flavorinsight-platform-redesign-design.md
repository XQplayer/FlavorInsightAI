# FlavorInsight AI 全站设计与网址迁移

日期：2026-10-04
状态：已确认设计；2026-10-04 按《FlavorInsight AI 全站设计修订要求》补充，待实施计划与代码实施
适用仓库：当前 `XQplayer/FlavorThresholdDB`，计划改名为 `XQplayer/FlavorInsightAI`

## 1. 决策与边界

FlavorInsight AI 是平台品牌名；FlavorThresholdDB 继续是平台内香气阈值与风味描述数据库的名称。全站统一设计覆盖首页、登录页、数据库入口与检索工作台、数据处理、数据分析以及资源中心。按页面分阶段落地，不改变现有检索、岛津分析与导出的科学规则。

新本地主页为 `http://127.0.0.1:5174/FlavorInsightAI/`。线上 GitHub Pages 项目站点以改名后的仓库 `FlavorInsightAI` 为承载，目标网址为 `https://XQplayer.github.io/FlavorInsightAI/`。旧 `/FlavorThresholdDB/` 网址不承诺继续可用，也不建设旧站跳转；仓库内当前使用说明中的旧平台链接应更新，`PROJECT_HISTORY.md` 等历史记录保留原始事实。数据库模块在新路径下仍保留自身检索入口，不因平台品牌改名而改称 FlavorInsight AI 数据库。

本轮全站登录页只完成视觉与入口，不接入新的全站身份认证，不要求登录才能使用当前本地功能，不收集或提交账号密码。岛津模块现有的可选账号/云端代码及权限逻辑不由新登录页替换。页面必须明确标示账号功能尚未启用，并提供“继续本地使用”入口；不得绘制貌似可提交但实际无效的表单。

全站首次访问默认显示英文；导航中的显式语言按钮可切换为中文，也可切回英文。用户已保存的语言偏好优先于首次默认值，跨页面保持一致。

## 2. 用户体验与页面职责

### 全站框架

顶部统一放置品牌、首页、FlavorThresholdDB、数据处理、数据分析、资源中心，以及中英文、主题和账号入口。公共导航、语言与主题偏好跨页面一致；语言按钮显示将切换到的语言，并具备可见焦点与明确可访问名称。窄屏以可操作的折叠菜单呈现，不遮挡内容或键盘焦点。

### 能力状态

所有模块先核定状态，再决定文案与交互。状态统一为四级：

| 状态 | 中文显示 | 交互规则 |
| --- | --- | --- |
| Available | 已上线 | 提供真实可用的主按钮、链接或功能入口。 |
| Beta | 测试中 | 可以进入，但需明确测试属性、限制与可能变化。 |
| In development | 开发中 | 仅展示说明，不伪装为可用按钮。 |
| Planned | 规划中 | 仅用于路线图或说明，不提供虚假交互。 |

同一规则适用于首页模块、数据分析、智能体与预测模型、资源中心及其英文文案。状态不能从品牌名中的“AI”推断；风味贡献评价的实际状态须在实施前核对现有功能。状态不能只通过颜色表达。

### 首页

作为品牌层，Hero 主标题固定为“FlavorInsight AI”，英文界面同样显示品牌名；FlavorThresholdDB 只在第二层数据库产品入口与功能导航出现。首页按“品牌 → 研究链条 → 平台模块 → FlavorThresholdDB／数据处理／数据分析／资源中心 → 证据链与使用边界”组织。研究链清楚说明“仪器数据—化合物鉴定—风味数据库—风味贡献评价—AI 解析与预测”，每项按四级状态标示。首屏提供进入数据库与数据处理的真实入口；示例数据必须可追溯，不能把未来的智能体、模型或分析能力说成已上线。

### 登录页

采用已确认的左右结构：全屏环境背景及深色遮罩，左侧品牌定位、能力说明与可追溯研究理念，右侧高对比度悬浮卡片。右侧采用“Account access / 账号访问”的账号服务状态结构，明确说明当前本地部署未启用全站账号认证；当前唯一主操作为“Continue locally / 继续本地使用”，须进入真实可用页面。不得显示真实或 disabled 的邮箱、密码输入框，也不得出现“忘记密码”“保持登录”“注册账号”等尚不存在的功能。未来账号能力可列为规划说明，但不能有伪交互。未来接入真实认证时，应沿用本页结构但另行设计会话、审批、错误、隐私、恢复与安全策略。

### FlavorThresholdDB 与检索

数据库概览继续介绍数据来源、热门化合物和检索入口；CAS、名称、阈值、来源、结构等科研证据保持现有可复核路径。检索工作台、结果表、来源徽标和导出不因视觉改版改变数据语义。数据密集区域采用稳定、清晰的实色面板。

### 数据处理

保留分析流程配置、数据导入、过程监控、质量门禁、错误证据和结果导出的现有执行逻辑。流程状态、警告与失败同时以文字和图标呈现，绝不只靠颜色。玻璃效果不能覆盖输入、日志、表格、质量门禁和数值。

### 数据分析与资源中心

统一页面框架并按四级状态标示。数据分析暂不冒充已部署的 AI 结果。资源中心区分已核验资源与规划内容，保留来源和更新状态。

## 3. 视觉系统

视觉策略是“品牌页面强调玻璃质感，科研工作台强调清晰数据”。参考 `VoltAgent/awesome-design-md` 中 Apple `DESIGN.md` 的留白、精确排版和受控层级，但不复制其商标、页面内容或完整品牌配色。现有根目录 `DESIGN.md` 是未提交的岛津工作台设计文件，必须保留；实施时将所选 Apple `DESIGN.md` 复制到独立参考目录并保留许可与出处，再从中提炼 FlavorInsight AI 自有设计规范，不覆盖根目录文件。

品牌氛围色仅用于首页和登录页：雾灰 `#D9DDD9`、灰蓝 `#AEB9BD`、灰紫 `#B7B1BD`、暖灰白 `#ECEAE5`。工作台采用独立的稳定表面令牌：应用画布 `#F7F8F7`、主表面 `#FFFFFF`、次表面 `#F1F3F2`、分隔线 `#DDE1E0`、主文字 `#252729`。背景色之间只能使用低对比、缓慢且自然的明度过渡，不将品牌氛围色直接铺满 GC–MS、QC、日志或结果表。

单一品牌操作色家族：`--accent-600: #315FCE`、`--accent-500: #4477DF`、`--accent-100: #E9EFFC`。实施时可在同一蓝色家族内为对比度小幅调整，但不能新增第二主品牌色或使用高饱和蓝紫粉渐变。成功、警告、失败和低置信度使用独立语义状态色，保持现有含义；任何新颜色组合必须逐项测量文字与控件对比度。

玻璃质感用于悬浮导航、登录卡边缘和少量重要控件：通过多层透明镜片、弧形边缘高光、局部低强度反射和明确的前后层级表达；不依赖高透明度或全页模糊。视觉重心约 80% 来自排版、布局与科研数据组织，约 15% 来自表面与层级，约 5% 来自玻璃和反射；这些是设计权重而非逐像素配额。浏览器内的光学效果不得降低文字对比度。`backdrop-filter` 不可用、用户偏好减少透明或启用降级模式时，仍须以实色表面保持完整、美观和清晰。数据表、输入框正文区、错误详情和运行日志使用不透明或接近不透明的表面。

避免彩虹玻璃、高饱和渐变、肥皂泡、漂浮水晶、液态金属、赛博朋克、无意义 3D、全组件发光、过度模糊及廉价塑料感。界面应呈现低噪声、轻盈、精密的系统工具气质。

全站 UI／英文统一选用 Inter，中文按 `PingFang SC`、`Microsoft YaHei`、`Noto Sans SC`、`system-ui` 顺序回退；字体无法加载时必须能以系统字体正常呈现。CAS、DOI、m/z、RI、ppm、μg/L 等科研编号与单位使用 `JetBrains Mono`、`SFMono-Regular`、`Consolas`、`monospace` 字体栈，但不强制所有中文表格内容使用等宽字体。大标题与正文有清晰字号阶梯；正文原则上不小于 16px，密集科研表格可按既有可读规范单独调校。正文与控件文字目标达到至少 WCAG AA 普通文字 4.5:1 对比度。交互目标至少约 44×44px，具备明显键盘焦点、触控间距、加载与错误反馈。动画不承载唯一信息，遵循 `prefers-reduced-motion`。桌面、平板和手机分别验收，避免横向页面溢出。

Galaxy 控件库只作为组件候选来源。采用某个按钮、输入或卡片前必须检查具体源码、交互状态、许可与署名，并适配现有 React/CSS 和全站视觉令牌；不因“玻璃”标签而照搬不适合科研界面的特效。

## 4. 技术边界与迁移顺序

1. 先建立项目自有设计令牌与页面级覆写规则。保留现有岛津工作台的状态语义和两种主题偏好，不对整个系统做机械反色。默认语言从现有中文改为英文；已保存的中英文偏好继续生效，按钮可双向切换，`html[lang]` 与可访问名称同步。
2. 先完成首页和登录页，再逐页统一数据库、数据处理、数据分析和资源中心的导航、容器、表单与状态组件。可采用渐进式页面改版，但所有页面最终遵循同一全站规范。
3. 新增明确的登录页路由与浏览器标题。未启用全站认证期间，账号入口进入状态明确的登录页；“继续本地使用”返回真实可用页面。旧岛津可选账号模块保持独立。
4. 将 Vite 基础路径和内部路由改到 `/FlavorInsightAI/`。SPA 深链接固定采用现有路径式路由加静态路由页面及 `404.html` fallback，不引入 HashRouter 或不必要的 BrowserRouter 依赖。同步更新静态深链接生成（含登录页）、公共资源引用、测试、脚本、环境配置说明、当前使用文档及部署工作流。逐条区分“平台路径”与仍应保留的数据库产品名、历史记录或外部数据标识。除了站内点击，还要在部署环境中直接粘贴、刷新每个深链接并检查资源与导航路径。
5. 只有在本地新路径构建与深链接通过后，才重命名 GitHub 仓库、更新本地 `origin`，再部署并验收新的 Pages 路径。仓库改名是发布操作，不与未验证的 UI 修改捆绑执行。旧线上路径不做跳转承诺。
6. 不自动将原始工作簿或分析结果上传到云端。改版不改变现有本地分析与可选云端留存的实际行为及文案边界。

### 科研语义不可变约束

视觉重构不得擅自改变以下字段、含义、默认行为和导出 schema：

- CAS 值、化合物名称及中英文名称映射。
- 阈值数值、原始单位、归一化单位、介质（Medium）和阈值类型（Threshold type）。
- 文献来源、证据等级、来源徽标及其含义。
- GC–MS 峰、RI、相似度、匹配结果及既有科学输出。
- 质量门禁状态、错误码、错误证据与部分结果下载逻辑。
- 既有排序、筛选、匹配、导出字段及导出 schema。
- 成功、警告、失败、低置信度等既有颜色语义。

如果 UI 需要引入新聚合、单位换算、隐藏字段、默认排序、颜色分类或简化视图，只要可能影响科学解释，就继续沿用已确认的业务逻辑；确需改变时应先单独取得用户确认，再实施并补充回归测试。

## 5. 错误处理与验收

页面加载、深链接、未启用账号入口和外部服务不可用均应给出明确状态及下一步操作；不能把占位内容画成可用功能。登录页不显示邮箱或密码框，也不能向任何服务提交密码。质量门禁失败必须维持现有错误码、错误证据和部分结果下载能力。

验收标准：

- 本地首页及数据库、检索、处理、分析、资源、登录深链接均在新基础路径下直接加载并可刷新；旧路径不作为通过条件。
- GitHub 仓库改名后，在新 Pages 环境直接粘贴、刷新首页及每个深链接；页面与资源无 404，内部导航留在新路径，当前使用文档的旧平台链接已更新。
- 首次访问默认英文；语言按钮可切换中文并切回英文，已保存偏好跨页面、刷新后继续生效。深浅主题和语言不创建平行设计系统。
- 四级能力状态与真实功能一致：仅 Available 和显式标记的 Beta 可提供入口；未部署的 AI 解释与预测不可伪装为结果。
- 深浅主题及窄屏布局可用；在 375px、768px、1024px、1440px 宽度检查无页面级横向溢出。科研状态色和表格分别验证，不做机械反色。
- 键盘导航、可见焦点、登录状态说明、颜色对比、减少动效和减少透明回退通过检查；关闭 `backdrop-filter` 后依然清晰可用。
- 现有平台、静态路由、数据库检索和岛津浏览器流程测试通过；代表性本地检索、GC–MS 分析、QC 与导出行为没有因 UI 改版改变。科研语义不可变约束逐项核对。
- 未启用的全站登录无邮箱／密码输入与虚假提交，“继续本地使用”能到达真实可用页面；数据分析中的未来 AI 能力继续明确标记为未部署。
