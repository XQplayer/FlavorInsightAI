## Distinct test layers and gaps

1. **Static routing:** existing phase 2 seven-case route test passed at that phase; phase 3 inspected `SKILL_ROUTING.md` but did not re-run a separate route harness. A route table is a policy, not proof of use.
2. **Agent discovery/read:** all five `SKILL.md` files were actually opened in fresh-context read-only task probes. This layer passed for the sampled tasks.
3. **Agent constraint-following:** the synthetic computations and refusals above show task-level effect; the GC-MS zero-area branch and hash mismatch were exercised. This layer passed for the sampled cases only.
4. **Automatic activation:** no Codex dispatcher/invocation telemetry was exposed; therefore **unverified** as a platform-wide property.
5. **Unavailable skill fallback:** the separately named probe below confirmed a safe task-level fallback. This does not prove every unavailable-skill scenario.

Future probes should run from a fresh session with archived tool/read logs, a concealed target-skill name where possible, and a rubric scored before the agent sees outcomes. Record nonselection as well as selection. Do not infer universal automatic activation from these five examples.
