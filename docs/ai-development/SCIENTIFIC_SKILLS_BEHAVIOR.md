**Observed:** five project Skills were discovered, opened and used in three fresh-context agent tasks with synthetic inputs. This verifies task-level behavior and recorded tool calls. It does not prove automatic platform-wide Skill dispatch or validate real research results.

## Audit records and method

The project has `.agents/skills/flavor-{gcms-processing,statistical-analysis,ml-validation,scientific-visualization,data-integrity}/SKILL.md`. The main task explicitly assigned three separate probes with each probe owning one evidence JSON under `docs/ai-development/phase4-probes/`; agents were told to read `AGENTS.md`, relevant implementation and the selected actual SKILL.md, run a calculation or project function, record commands/output, and preserve parallel work. Their raw records are `gcms_integrity.json`, `stats_ml.json` and `visual_fallback.json`; all parse as JSON. This is actual subagent task execution, not a config-only discovery test. No research files, application behavior or production data were changed by the probes.

## Interpretation and remaining gap

Actual agent read and behavior are supported by the saved prompts and command/output records. These probes were explicitly assigned by the main agent; no telemetry proves Codex automatically chose these Skills for an unsolicited user request. The fallback name was deliberately absent. No independent method reviewer, empirical workbook, rendered figure, actual permutation-model run or production result was tested. Future validation should run blinded tasks under a platform instrumented dispatcher, retain raw invocation telemetry, and independently score decisions before claiming automatic activation reliability.
